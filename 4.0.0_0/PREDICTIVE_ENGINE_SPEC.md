# Predictive Chart Engine — техническая спецификация для Pocket Tracker 4.0

Статус: проектная спецификация. Основана на текущей ветке `feature/pocket-tracker-4.0` и исходниках каталога `4.0.0_0/`. Не является подтверждением прогнозной точности или совместимости с текущим production-интерфейсом Pocket Option.

## 1. Цели и границы

Predictive Chart Engine — независимый модуль расширения Pocket Tracker 4.0. Он использует только котировки OTC, полученные из WebSocket-потока Pocket Option. Внешние котировочные API и подмена источника цены не используются.

Поддерживаемые горизонты: 60, 120, 180, 240 и 300 секунд. Для каждого актива и горизонта формируется отдельный прогноз и отдельная статистика.

Требования:
- шесть моделей: linear, exponential, polynomial, momentum, cyclical, ensemble;
- автоматический выбор модели отдельно для каждой OTC-пары и каждого горизонта;
- сохранение неизменяемого прогноза до момента оценки;
- независимый учёт фактического результата и ошибки;
- режимы сигналов: indicators, predictive, combined;
- настройка OTC-пар, горизонта, порога уверенности, автоставок и лимита одновременных сделок;
- отдельная вкладка PREDICTIVE и отдельное хранилище настроек/статистики;
- отсутствие обязательного DEMO-этапа, принудительного подтверждения REAL и блокировки включения автоторговли. Выбор DEMO/REAL остаётся настройкой пользователя.

Цель 80%+ — исследовательский ориентир, а не гарантируемое свойство системы. Интерфейс показывает фактическую выборочную точность, размер выборки и доверительный интервал; до достаточной выборки отображается «Недостаточно данных».

## 2. Что уже есть в текущей ветке

В `manifest.json` ветки `feature/pocket-tracker-4.0` файл `predictive-engine.js` уже подключён в MAIN world перед `inject.js`. В `inject.js` найдено событие `quotes/stream`, которое публикует `POROBOT_WS_PRICE` с активом, ценой и timestamp. Поэтому отдельный сборщик котировок с новым WebSocket-перехватчиком не нужен: TickCollector должен подписываться на существующий поток.

В `predictive-engine.js` уже есть предварительный класс `PT4PredictiveEngine`, шесть идентификаторов моделей, пять горизонтов, очередь незавершённых прогнозов и базовый расчёт статистики. Однако текущая реализация — прототип, а не готовый торговый движок.

В текущем состоянии обнаружены пробелы:
- модуль не связан с UI: нет вкладки PREDICTIVE, графика, настроек и отображения статистики;
- `POROBOT_PREDICTIVE_UPDATE` не обрабатывается в `content.js`;
- прогноз не передаётся в существующий механизм сигналов и автоторговли;
- настройки и статистика Predictive Engine не сохраняются между перезапусками;
- `confidenceFloor` объявлен, но не применяется; текущая confidence-оценка не калибрована и не является вероятностью выигрыша;
- polynomial-модель сейчас фактически использует линейную регрессию с эвристической поправкой, а не квадратичную аппроксимацию;
- выбор ensemble опирается преимущественно на долю верных направлений, а не на полноценную out-of-sample оценку ошибки;
- оценка выполняется по первому пришедшему тику после времени экспирации без контроля задержки и качества временной метки;
- накопленная статистика хранится только в памяти;
- в текущей ветке есть ограничения запуска по распознаванию типа счёта и отдельное подтверждение REAL в `panel.js`/торговом ядре. Это противоречит зафиксированному требованию о самостоятельном выборе режима пользователем и должно быть согласованно переработано в рамках отдельной задачи, не меняя источник котировок.

## 3. Архитектура модулей

Рекомендуемая структура:

```
4.0.0_0/
  predictive/
    predictive-engine.js       # фасад и жизненный цикл
    tick-collector.js          # нормализация и буферизация OTC-тиков
    formula-library.js         # шесть чистых математических моделей
    model-evaluator.js         # отложенная оценка и метрики
    adaptive-selector.js       # выбор модели/весов по паре и горизонту
    forecast-manager.js        # расписание прогнозов и неизменяемые записи
    predictive-storage.js      # версия схемы, сохранение/восстановление
    predictive-signals.js      # преобразование прогноза в сигнал
    predictive-auto-trade.js   # адаптер к существующему торговому ядру
    predictive-ui.js           # UI вкладки PREDICTIVE
    predictive-chart.js        # отрисовка факта и прогноза
```

Если сборка должна оставаться плоской, файлы можно разместить в `4.0.0_0/`; логические границы модулей сохраняются. Не дублировать WebSocket interception и не переносить торговую логику из `inject.js`.

Поток данных:

```
Pocket Option WebSocket
  -> inject.js: POROBOT_WS_PRICE
  -> TickCollector
  -> ForecastManager
  -> FormulaLibrary (6 моделей × 5 горизонтов)
  -> AdaptiveSelector
  -> immutable forecast record
  -> PredictiveUI / ModelEvaluator
  -> PredictiveSignals
  -> существующий сигнал/торговый адаптер
```

## 4. Контракт котировки и OTC-фильтр

Нормализованная запись тика:

```js
{ asset: "EURUSD_OTC", price: 1.0842, timestamp: 1790000000000, source: "pocket-option-ws" }
```

Обязательные проверки:
- актив присутствует в каталоге Pocket Option и помечен как OTC;
- цена конечная и больше нуля;
- timestamp конечный, монотонный в пределах актива;
- повторные одинаковые тики не создают искусственную частоту наблюдений;
- нормализация символа не должна терять суффикс OTC;
- обычные, крипто-, товарные и индексные активы не включаются в FX OTC-режим, если пользовательский фильтр явно не разрешает их отдельным типом.

Для мульти-парного режима использовать уже существующий каталог активов и механизм подписок `QuotexCore`. TickCollector агрегирует поток по активу; он не должен подписывать WebSocket повторно.

## 5. Математические модели

Все модели получают одинаковый ограниченный по времени ряд наблюдений и возвращают прогноз цены для заданного горизонта, диагностические признаки и признак пригодности.

1. **Linear** — робастная оценка скорости и ускорения по скользящему окну. Экстраполяция ограничивается волатильностью, чтобы выброс не создавал нереалистичную траекторию.
2. **Exponential** — Holt linear (уровень + тренд) с адаптивными коэффициентами сглаживания. Параметры оцениваются только на прошлом окне.
3. **Polynomial** — квадратичная регрессия по центрированному/масштабированному времени; регуляризация и ограничение кривизны обязательны для устойчивой экстраполяции.
4. **Momentum** — быстрый и медленный EMA доходности, затухание импульса по горизонту и поправка на текущую волатильность.
5. **Cyclical** — поиск устойчивого периода через автокорреляцию/спектральную оценку; модель отключается при недостаточной выраженности цикла.
6. **Ensemble** — взвешенная комбинация доступных моделей. Веса вычисляются только из ранее завершённых out-of-sample прогнозов для конкретной пары и горизонта. До накопления минимальной выборки применяется нейтральное равное взвешивание пригодных моделей.

Модель должна возвращать `{ price, direction, diagnostics, valid }`. Невалидный прогноз не участвует в выборе и ансамбле. Никакая модель не имеет права использовать будущие тики или результаты прогнозов, которые ещё не завершились.

## 6. Выбор модели и уверенность

Ключ адаптации: `asset + horizonSeconds + modelId`. Статистика разных активов и горизонтов не смешивается при выборе лучшей модели.

Метрики по каждой модели:
- directional accuracy;
- число прогнозов;
- MAE и нормализованная MAE;
- Brier score для вероятностной оценки направления;
- доля нейтральных/пропущенных прогнозов;
- калибровка confidence по диапазонам.

AdaptiveSelector:
1. исключает модели с недостатком завершённых наблюдений;
2. ранжирует оставшиеся по заранее определённой комбинации directional loss и normalized MAE;
3. применяет сглаживание весов, чтобы выбор не переключался из-за одного результата;
4. выбирает лучшую модель или ансамбль;
5. возвращает «insufficient data», если ни одна модель не достигла минимального объёма выборки.

Confidence не вычисляется простой функцией абсолютного изменения цены. Она калибруется по историческим out-of-sample результатам модели для соответствующего актива и горизонта. До калибровки UI показывает «не откалибрована», а порог confidence не должен маскировать это состояние.

## 7. Неизменяемый прогноз и независимая оценка

Каждый прогноз записывается один раз при выпуске:

```js
{
  id, asset, issuedAt, targetAt, horizonSeconds,
  entryPrice, predictedPrice, direction, modelId,
  modelPredictions, confidence, selectorVersion,
  status: "pending"
}
```

После записи поля прогноза не меняются. Исправление или повторный расчёт создаёт новую запись, а не перезаписывает старую.

На `targetAt` фиксируется первая валидная котировка с timestamp не раньше целевого времени. Записываются фактический timestamp, задержка относительно targetAt и фактическая цена. Если задержка выше установленного лимита или поток был разорван, прогноз получает статус `invalid` и не попадает в accuracy.

Правильность направления:
- UP: фактическая цена выше entryPrice;
- DOWN: фактическая цена ниже entryPrice;
- равная цена: DRAW/NEUTRAL, отдельно от wins/losses.

Для каждой из шести моделей сохраняется собственный прогноз, чтобы оценивать все модели на одном и том же фактическом исходе. Нельзя оценивать только выбранную модель: иначе сравнение будет смещённым.

Обучение/адаптация и отчётная проверка разделяются по времени. Для оценки применяются rolling/walk-forward интервалы; параметры модели на момент прогноза фиксируются. Отчётная accuracy не должна включать прогнозы, использованные для подгонки параметров задним числом.

## 8. Режимы сигналов

Настройка `signalSource`:
- `indicators` — используется только существующая система индикаторов;
- `predictive` — решение строится только по Predictive Engine;
- `combined` — совместная оценка индикаторов и прогноза.

В combined задаются веса и минимальное согласие. Если направления конфликтуют, результат по умолчанию — `NO_TRADE`; настройка должна быть явной. Predictive Engine не меняет алгоритмы индикаторов и не подменяет их статистику.

Структура сигнала:

```js
{
  id, asset, direction, horizonSeconds,
  confidence, selectedModel, modelAgreement,
  issuedAt, targetAt, source: "predictive" | "combined"
}
```

Сигнал должен иметь уникальный ID, чтобы одна и та же прогнозная запись не открывала повторные сделки на каждом тике.

## 9. Автоторговля и настройки счёта

PredictiveAutoTrade — тонкий адаптер. Он передаёт валидный сигнал в существующий торговый механизм, не дублируя `executeTrade`, MoneyManager, учёт открытых сделок и обработку результатов.

Настройки пользователя:
- accountMode: `demo` или `real`;
- autoTrade: boolean;
- signalSource: `indicators` / `predictive` / `combined`;
- selected OTC pairs или all OTC;
- expiration: 1–5 минут;
- minConfidence;
- baseBet / выбранный money management;
- maxConcurrentTrades;
- allowConflictingSignals: false по умолчанию.

Не вводить обязательный demo-first, обязательное подтверждение REAL или скрытый запрет включения автоставок. Выбранный пользователем accountMode передаётся торговому ядру явно. Фактический режим платформы можно показывать как диагностическую информацию, но не менять выбор пользователя молча. При несовпадении выбранного и фактического режима система должна явно сообщить о несоответствии; способ поведения при таком несоответствии фиксируется отдельно до реализации, чтобы не отправлять ордер на неверный счёт.

## 10. UI вкладки PREDICTIVE

Разделы:
- состояние движка и источник котировок;
- активная OTC-пара и выбор горизонта;
- UP/DOWN/NEUTRAL, прогнозная цена и время выпуска;
- график фактической истории и отдельная пунктирная прогнозная траектория;
- выбранная модель и вклад всех шести моделей;
- confidence и статус калибровки;
- таблица accuracy/MAE/выборки по пяти горизонтам;
- список незавершённых и завершённых прогнозов;
- Signal Source, список OTC-пар, минимальная уверенность;
- Auto Trade, сумма, лимит одновременных сделок и accountMode.

График не должен рисовать прогноз как уже случившуюся цену. Фактический участок и прогнозный участок визуально разделены; прогноз фиксируется на момент выпуска.

## 11. Хранение и производительность

Все ключи имеют префикс `pt4Predictive` и отдельную версию схемы. Сохраняются пользовательские настройки, завершённые метрики, pending-прогнозы и ограниченная история. Большие массивы тиков не записываются в storage на каждом событии; используются кольцевые буферы в памяти и пакетная запись агрегатов.

Нужны лимиты:
- максимальная глубина тиков на актив;
- максимальное число pending-прогнозов;
- ограниченная история прогнозов;
- debounce/throttle для UI;
- пакетные обновления DOM;
- корректное восстановление после перезапуска без повторного расчёта уже закрытых прогнозов.

## 12. Этапы реализации

1. **Audit & baseline:** зафиксировать контракты `POROBOT_WS_PRICE`, `POROBOT_SIGNAL`, `POROBOT_CORE_CMD`, активный каталог и мульти-парные подписки.
2. **Core:** выделить TickCollector, FormulaLibrary и единый контракт модели; покрыть синтетическими тестами.
3. **Evaluation:** immutable forecast, отложенная оценка, метрики и walk-forward тесты.
4. **Adaptive selection:** per-asset/per-horizon выбор, ensemble и калибровка confidence.
5. **Integration:** режимы indicators/predictive/combined и передача сигналов в существующий торговый адаптер.
6. **UI & storage:** вкладка PREDICTIVE, график, настройки и история.
7. **Account settings:** согласовать и реализовать пользовательский выбор DEMO/REAL без demo-first и дополнительных блокировок автоставок.
8. **Verification:** синтаксис, unit-тесты моделей, тесты отсутствия look-ahead, тесты повторных сигналов, статическая проверка manifest и ручная проверка в браузере. До реального запуска не заявлять о достигнутой точности.

## 13. Критерии готовности

- Для каждой выбранной OTC-пары доступны прогнозы на все пять горизонтов.
- Все шесть моделей оцениваются на одних и тех же закрытых прогнозах.
- Прогноз после выпуска неизменяем.
- Метрики раздельны по паре и горизонту и переживают перезапуск.
- Нет утечки будущих данных в выбор модели или confidence.
- PREDICTIVE UI показывает прогноз, фактическую траекторию, модель, confidence, выборку и точность.
- Все три Signal Source работают и не дублируют существующую торговую логику.
- Пользователь выбирает DEMO/REAL и управление автоставками без обязательного demo-first.
- Система не заявляет 80%+, пока достаточная независимая выборка не подтверждает этот показатель.
