# Архитектура расширения PocketOption Signal 3.6.0

> Документ описывает исходный код каталога `3.6.0_0/` в репозитории `Maestro-777/pocket-tracker` (ветка `main`). Это разбор реализации, а не гарантия работы внешних серверов или Windows-приложения. При изменении исходников документ нужно сверять с кодом.

## 1. Назначение и состав

Расширение Chrome Manifest V3 для сайта Pocket Option. Основные части:

| Файл / каталог | Назначение |
|---|---|
| `manifest.json` | Manifest V3, права, точки входа и URL-совпадения |
| `background.js` | Service worker: сообщения, хранилище, окно панели, маркет пресетов |
| `inject.js` | Код в MAIN world: перехват WebSocket Pocket Option, анализ данных, графические индикаторы и торговое ядро |
| `content.js` | UI бота, настройки, журнал, статистика, связь с ядром и фоновым процессом |
| `bridge/bridge-client.js` | Локальный WebSocket-мост с Windows-приложением, лицензия, динамическое включение скриптов и телеметрия |
| `bridge/grant.html/js/css` | Страница запроса дополнительного доступа к сайтам |
| `market/ext-host.js` | Адаптер API маркета из content script в background |
| `market/market.js` | UI маркета пресетов и операции с каталогом/библиотекой |
| `market/qrcode.js` | QR-код (вспомогательная библиотека) |
| `panel/panel.html/js/css` | Отдельное popup-окно управления |
| `css/bot-ui.css` | Стили интерфейса, внедряемого на торговую страницу |
| `icons/` | Иконки расширения |

## 2. Точки запуска и разрешения

В `manifest.json` указано:

- `manifest_version: 3`, версия `3.6.0`;
- service worker — `background.js`;
- на `https://pocketoption.com/*` и `https://*.pocketoption.com/*` при `document_start` запускаются два набора скриптов:
  1. `inject.js` в `world: MAIN`, `all_frames: true`;
  2. `market/ext-host.js`, `content.js`, `market/qrcode.js`, `market/market.js` и `css/bot-ui.css` в обычном content-script world;
- обязательные разрешения: `storage`, `tabs`, `windows`, `scripting`, `alarms`;
- host permissions: Pocket Option и `pocketoption-signal.online`;
- `optional_host_permissions: ["*://*/*"]` — дополнительный доступ ко всем сайтам запрашивается отдельно;
- `panel/*` и `inject.js` объявлены как web-accessible resources для страниц Pocket Option.

Важно различать MAIN world и isolated content-script world. `inject.js` работает рядом с кодом сайта и видит его WebSocket/JS-объекты. `content.js` имеет доступ к API расширения и отвечает за интерфейс и коммуникацию с background.

## 3. Два независимых механизма подключения

В расширении есть два разных соединения, которые нельзя путать.

### 3.1. Подключение к Pocket Option

Это не отдельный вход по логину/паролю. Расширение встраивается в страницу Pocket Option:

1. Браузер загружает `inject.js` в MAIN world на страницах домена Pocket Option.
2. `inject.js` сохраняет оригинальный `window.WebSocket`, заменяет глобальный конструктор обёрткой и создаёт настоящий сокет через оригинальный конструктор.
3. Для созданных сайтом WebSocket-соединений расширение перехватывает исходящие `send()` и входящие `message`.
4. Входящие текстовые события Socket.IO разбираются как JSON-массивы вида `[eventName, payload]`; бинарные данные декодируются через MessagePack-декодер, включая данные, пришедшие как `ArrayBuffer` или `Blob`.
5. События передаются обработчикам `handlePOEvent()`: в частности, распознаются `user_ready`/`successauth`, `updateAssets`, данные графика/котировок и результаты сделок.
6. Данные используются торговым ядром и передаются в UI через `window.postMessage` с типами `POROBOT_*`.

Таким способом код получает данные сайта без постоянного опроса DOM. DOM при этом тоже используется: для определения текущего актива, проверки торгового интерфейса, установки суммы/экспирации и нажатия кнопок.

### 3.2. Подключение к Windows-приложению (локальный bridge)

Файл: `bridge/bridge-client.js`. В Chrome он подключается из `background.js` через `importScripts("bridge/bridge-client.js")`.

Параметры локального протокола:

- WebSocket URL: `ws://127.0.0.1:{port}/pos-bridge`;
- порты по порядку: `47821`, `47822`, `47823`;
- версия протокола: `v: 1`;
- при открытии отправляется `{v:1, type:"hello", ext:<version>, browser:<name>}`;
- `ping` получает ответ `pong`;
- сообщение `state` содержит `enabled` и `token`.

Переподключение:
- при закрытии сокета расширение сбрасывает состояние в `enabled:false`, снимает динамические скрипты и отправляет `POS_BRIDGE_OFF` открытым вкладкам-зеркалам;
- перебирает три порта с короткой паузой 300 мс между портами;
- после полного круга увеличивает backoff от 1 секунды до максимума 30 секунд;
- соединение повторно проверяется также alarm-задачей раз в минуту и при старте браузера.

### 3.3. Проверка лицензии Windows-приложения

Bridge получает токен от локального приложения, но проверяет его на стороне расширения:

- ожидается compact JWS из трёх частей;
- в заголовке должны быть `alg: "ES256"` и `typ: "POS-ACT"`;
- подпись проверяется через WebCrypto `crypto.subtle.verify` по встроенному публичному ключу ECDSA P-256;
- payload должен содержать `exp`, который ещё не истёк;
- токен, отозванный сервером ранее, запоминается в `chrome.storage.local` под `posTelemetryKilled` и повторно не принимается.

Состояние применяется последовательно через Promise-очередь `applying`, чтобы параллельные события не перемешивали включение/выключение.

### 3.4. Динамическое включение на зеркалах

При валидном токене и наличии host permission вызывается `scripting.registerContentScripts()`. Регистрируются два набора:

- `pos-bridge-main`: `inject.js` в MAIN world;
- `pos-bridge-iso`: `market/ext-host.js`, `content.js`, `market/qrcode.js`, `market/market.js`, CSS.

Они запускаются на `http://*/*` и `https://*/*`, но исключают Pocket Option: там уже действуют статические записи манифеста. Используется `document_start`, `allFrames:true`, `persistAcrossSessions:false`.

Если лицензия валидна, но нет разрешения `*://*/*`, открывается `bridge/grant.html`. Кнопка вызывает `permissions.request({origins:["*://*/*"]})` непосредственно в обработчике клика. После разрешения пользователь должен обновить вкладку зеркала. При отказе расширение остаётся ограничено Pocket Option.

## 4. Поток сообщений внутри расширения

Основные направления:

```
Pocket Option page / WebSocket
        ↕
inject.js (MAIN world, анализ и торговое ядро)
        ↕ window.postMessage: POROBOT_*
content.js (UI, настройки, журнал)
        ↕ chrome.runtime.sendMessage
background.js (service worker)
        ↕ chrome.tabs.sendMessage
content.js во вкладках
```

Примеры сообщений/команд:

| Тип | Назначение |
|---|---|
| `POROBOT_START` | Запуск ядра с конфигурацией |
| `POROBOT_STOP` | Остановка ядра |
| `POROBOT_CORE_CMD` | Команда ядру: например, `START`, `STOP`, `PATCH_CONFIG`, `SET_OVERLAY` |
| `POROBOT_LOG` | Лог ядра для UI |
| `POROBOT_STATS` | Обновление статистики |
| `POROBOT_TRADE` | Информация о сделке |
| `POROBOT_SIGNAL` | Карточка сигнала |
| `POROBOT_TRADE_RESULT` | Результат сделки |
| `POROBOT_BALANCE` | Баланс/тип счёта |
| `POS_BRIDGE_OFF` | Локальное приложение отключило bridge; остановить ядро и убрать панель |

`background.js` ретранслирует `POROBOT_START`, `POROBOT_STOP`, `POROBOT_CORE_CMD` и `BOT_FOCUS_PAIR` в указанную вкладку (`tabId`) или активную вкладку. `content.js` во фреймах проверяет наличие торгового интерфейса перед передачей команд ядру.

## 5. Основные функции торгового ядра

### 5.1. Получение рыночных данных

`inject.js` перехватывает WebSocket Pocket Option, собирает каталог активов и псевдонимы символов, получает данные котировок/свечей/графика и результаты сделок. Бинарные сообщения обрабатываются MessagePack-декодером. Обработчики событий обновляют внутреннее состояние ядра (`window.__poCore`).

### 5.2. Анализ и сигналы

Класс `QuotexCore`:
- запускает цикл анализа примерно каждые 1,5 секунды;
- синхронизирует актив из DOM примерно каждые 800 мс;
- проверяет, что текущий frame действительно содержит торговый UI;
- использует конфигурацию выбранных индикаторов, режим фильтрации, подтверждение, экспирацию и money management;
- публикует сигналы/логи/результаты через события `POROBOT_*`.

Набор стратегий и параметры задаются в `content.js`; интерфейс хранит настройки, а ядро выполняет вычисления и контролирует состояние сделок.

### 5.3. Индикаторы непосредственно на графике Pocket Option

Модуль `PosChartOverlay` в `inject.js` синхронизирует индикаторы через WebSocket-события Pocket Option, а не через клики по меню:

- `indicator/load`;
- `indicator/create`;
- `indicator/update`;
- `indicator/delete`.

Для создания формируется `requestId`, `chartId`, тип, настройки и `visible:1`. Поддерживаемые типы в таблице управления включают BB, RSI, MACD, Stochastic (в коде `so`), CCI, SAR и MA/EMA/SMA. Есть защита от повторных неудачных create-запросов и лимит до 12 индикаторов на графике.

### 5.4. Автоматическая торговля

В `executeTrade()` последовательность такая:

1. установить сумму ставки через DOM/API-хелперы страницы;
2. установить время экспирации;
3. найти активную кнопку UP/CALL или DOWN/PUT по CSS-селекторам (с fallback по тексту Buy/Sell / Купить/Продать);
4. нажать кнопку.

Функция возвращает успех только если синхронизация ставки, экспирации и нажатие кнопки прошли успешно. Это реальное управление торговым интерфейсом; включение автоторговли может приводить к финансовым операциям.

### 5.5. UI и локальные данные

`content.js` создаёт панель в верхнем frame и обслуживает вкладки сигналов, журнала, статистики, настроек и контактов. Состояние и настройки читаются/пишутся через `chrome.storage.local`. Отдельное окно `panel/panel.html` отправляет команды через background. По нажатию на иконку расширение активирует существующую вкладку Pocket Option или открывает торговую страницу.

## 6. Маркет пресетов и отдельная авторизация

Маркет — отдельный сетевой контур, не связанный с лицензией Windows bridge.

Поток:
1. `market.js` вызывает API-адаптер `posApp`;
2. в расширении `market/ext-host.js` отправляет сообщение в background;
3. `background.js` выполняет POST на `https://pocketoption-signal.online/api/market.php`;
4. токен добавляется в background и не передаётся обратно в страницу.

Публичные действия: `catalog`, `get`.

Действия, требующие входа: `my`, `profile`, `save`, `update`, `delete`, `publish`, `unpublish`, `install`, `uninstall`, `buy`, `invoice`, `invoice_tx`.

Вход:
- email + пароль, опционально TOTP;
- `action:"login"`;
- пароль не сохраняется;
- выданный JWS токен и срок `token_exp` сохраняются в `chrome.storage.local.posMarketAuth`;
- истёкший токен удаляется; ошибки `invalid_token` и `device_removed` также удаляют сохранённый токен;
- logout удаляет `posMarketAuth`.

Запросы отправляются как JSON-строка с `Content-Type: text/plain;charset=UTF-8` — комментарий в коде объясняет это обходом CORS preflight. Перед отправкой проверяется whitelist action и ограничение размера тела 16 000 символов.

## 7. Телеметрия Windows bridge

Телеметрия отправляется только при валидном activation token. Источником событий выступает `content.js`, который отправляет `POS_TELEMETRY` в background.

Собираемые поля состояния вкладки:
- активный торговый инструмент;
- тип счёта demo/real;
- включён ли бот;
- демо- и реальный баланс;
- снимок конфигурации стратегии (максимум 2 КБ).

Поля сделки:
- id и время;
- актив, направление, сумма, прибыль, результат;
- тип счёта, признак auto;
- стратегия и снимок конфигурации.

Состояния вкладок считаются актуальными 150 секунд. Сделки ставятся в очередь `posTelemetryQueue` (максимум 300), отправляются пачками до 100. Состояние отправляется по минутному alarm, сделка инициирует отправку примерно через 5 секунд. Endpoint: `https://pocketoption-signal.online/api/telemetry.php`. При сетевой ошибке очередь сохраняется для следующей попытки. При ответах `revoked`, `expired`, `device_removed`, `device_limit` токен помечается отозванным, очередь очищается и состояние bridge применяется повторно.

В Chrome функция `hasDataConsent()` возвращает true без отдельного permission prompt. В Firefox проверяется optional permission `data_collection` для `websiteActivity` и `financialAndPaymentInfo`; запрос согласия совмещён с запросом доступа к сайтам. Отказ от сбора данных не блокирует overlay.

## 8. Хранилище: ключи, которые важно знать

| Ключ | Для чего |
|---|---|
| `posMarketAuth` | Авторизация маркета: token, exp, email |
| `posBridgeGrantShown` | Не показывать повторно grant-страницу в пределах session storage |
| `posTelemetryQueue` | Очередь сделок для телеметрии |
| `posTelemetryKilled` | Токен bridge, отозванный сервером |
| `panelWindowId` | ID отдельного popup-окна |
| `pos_lang` | Язык интерфейса |
| настройки бота | Сумма, стратегии, экспирация, money management и прочие параметры UI |

При установке `background.js` записывает начальные значения `botEnabled`, `tradingPair`, `indicator`, `moneyManagement`, `baseBet`, `martingaleMultiplier`, `parlaySteps`.

## 9. Как добавлять новые возможности

Рекомендуемое разделение ответственности:

1. **Новая настройка UI** — добавить элемент и обработчик в `content.js`; сохранить значение через существующий механизм настроек.
2. **Новое действие ядра** — определить команду в `POROBOT_CORE_CMD`, обработать её в message handler `inject.js`, не смешивать UI с торговой логикой.
3. **Новые данные Pocket Option** — изучить реальный WebSocket event в `inject.js`, добавить отдельную ветку в `handlePOEvent()`, нормализовать payload и передавать в ядро/UI.
4. **Новое действие background** — добавить отдельный тип сообщения в `background.js`, валидировать отправителя и параметры, возвращать ответ через `sendResponse`.
5. **Новая операция маркета** — добавить action в whitelist `MARKET_PUBLIC` или `MARKET_PRIVATE`, затем вызывать её через `market.js → ext-host.js → background.js`. Не переносить токен в content script.
6. **Новая функция Windows-интеграции** — согласовать тип сообщения и формат payload с локальным сервером Windows-приложения; проверить версию протокола `v:1`, поведение при разрыве связи и истечении токена.
7. **Телеметрия** — добавлять только необходимые поля, ограничивать размеры/типы данных, учитывать согласие и обновлять документацию по отправляемым данным.

Перед изменением торговой логики проверять работу в демо-режиме. Команды, которые могут выставить сделку, должны быть явно отделены от диагностических команд и иметь понятный переключатель/подтверждение.

## 10. Замечания по безопасности и надёжности

Это наблюдения по клиентскому коду, не утверждение о наличии эксплуатации:

- `content.js` содержит строковую константу `_RS` для HMAC-подписи запросов `/api/check.php`. Секрет, встроенный в распространяемый JavaScript, можно извлечь; его нельзя считать надёжным секретом между клиентом и сервером. Серверу следует опираться на полноценную проверку авторизации/подписи и rate limiting, а не на скрытость этой строки.
- Взаимодействие MAIN world ↔ content script использует `window.postMessage(..., '*')`. Для входящих сообщений желательно проверять `event.source`, origin (где применимо), тип и схему payload; не считать события страницы доверенными командами.
- В `background.js` для POS_MARKET проверяется `sender.id`, но другие обработчики сообщений также стоит ограничить допустимыми типами, отправителями и формой данных.
- `optional_host_permissions: ["*://*/*"]` — широкое разрешение. Оно включается только после пользовательского запроса, но следует объяснять, что динамические скрипты могут запускаться на зеркалах и других сайтах, подходящих под разрешение.
- Телеметрия содержит сведения о торговом инструменте, типе счёта, балансе, стратегии и сделках. Это финансово чувствительные данные; интерфейс согласия и политика приватности должны описывать их точно.
- Автоторговля нажимает реальные кнопки Buy/Sell. Нужны явное согласие пользователя, безопасные значения по умолчанию и проверки демо/реального счёта.
